## 4. 台股最小報價單位

quotes 保存官方 `asset_type` 後，report 依官方級距判定調查門檻：

| 類型 | 級距 |
|---|---|
| 股票 | 未滿 10 元 0.01；10 至未滿 50 元 0.05；50 至未滿 100 元 0.1；100 至未滿 500 元 0.5；500 至未滿 1000 元 1；1000 元以上 5 |
| ETF | 未滿 50 元 0.01；50 元以上 0.05 |

上櫃準用相同級距，美股維持每股 0.01 美元。級距來自 TWSE 公開規則（見查核來源）；公司網路的 TLS 檢查代理使官方頁面無法在本機工具內直接抓取驗證，因此以公開規則為依據，並以觀測到的官方收盤價是否落在級距倍數上作為佐證。migration 0003 之前寫入的報價沒有類型，報告仍輸出 `tick_size_unknown` 且不進入吻合率分母，不回填也不推測。

### 實際收到的資料

2026-09-23 以 `report --campaign-id f0a98b5a-8027-44b4-996e-b3fbf9ff2afd` 產出報告（`output/reports/campaign-f0a98b5a-.../20260923T060936Z/`）：

| 指標 | 結果 |
|---|---|
| 首次取得成功率 | 10,510 / 10,581（**99.33%**） |
| 重試後成功率 | 10,553 / 10,581（99.74%） |
| 名單涵蓋率 | 6 / 11（**54.55%**） |
| 排程覆蓋率 | 886 / 3,600（**24.61%**） |
| 時效達標率 | 3,466 / 17,305（20.03%），判定**證據不足** |

**抓價本身沒有問題**：真的送出去的請求 99.33% 拿到價格。問題是送出去的太少。

五檔美股（AAPL、MSFT、BRK.B、VOO、QQQ）**完全沒有嘗試紀錄**（`no_attempt`），因此涵蓋率的 6 檔全是台股。campaign 下六個 run 的狀態解釋了原因：

```
09-08 12:13  interrupted
09-09 00:44  interrupted
09-10 00:57  interrupted
09-11 05:38  interrupted
09-14 08:17  interrupted    ← 09-11 至 09-14 完全空白
09-15 00:46  running（從未結束）
```

六個 run 無一正常結束，中間有三天空白。`interrupted` 表示行程被中止（關機、休眠、Docker 重啟），monitor 的續接設計如預期運作，但累積結果是四分之三的預定輪次從未發生。美股盤中對應台灣深夜，那幾段空白正好落在夜間，因此美股整批錯過。

**這是開發機的執行條件問題，不是程式缺陷。** 要補完需要一台不休眠、跨夜開著的機器連續約一週。

### 為什麼不重跑

雲端第一階段已經不走這條路：

| V10 的組成 | 現況 |
|---|---|
| 每市場三個完整交易日 | **作廢**。那是常駐 monitor 的抽樣方法；`D3` 改為請求內同步完成 |
| 各來源獨立指標 | **作廢**。`Dashboard.__init__` 清空 `comparison`，雲端只有 Yahoo 一個來源 |
| 缺口清單 | **作廢**。`min=0` 的停機是 `D5` 的成本設計，不是缺陷 |
| 同時間與價格口徑比對 | **仍然必要**，見下 |

[雲端部署第一階段執行計畫](cloud-phase-1-plan.md) 的範圍表已明文把「常駐 monitor、七天觀測、固定排程抓價」列為不納入。為了一個已經不會存在的執行模型再跑一週觀測，不會產生任何對雲端有效的證據。

### 移交 `C7-6` 的兩項（**不得隨本步驟一併丟棄**）

拆解後有兩件事與觀測時長無關、與雲端同樣相關，而且**在新設計裡比舊設計更重要**：

1. **盤中抓取確實取得當日成交，而非收盤舊價**（驗收計畫第 1 節第 3 項原話：「排除只有歷史資料卻誤判成功的情況」）。
2. **抓到的價格與官方口徑一致**（V10 的價格比對）。

之所以更重要：舊模型有排程，抓價時間已知；新模型由使用者任意時間觸發，**半夜按「更新報價」會拿到收盤價**。程式已會標 `stale`／`market_closed`／`freshness_unknown` 並逐股顯示（`static/app.js` 的 labels 表與逐股 meta 欄，含價格時間、取得時間與交易時段），但**那些旗標標得對不對從未被驗證**。本次報告的「時效達標率為證據不足：有超過門檻的樣本，且無法獨立判斷是否因無成交而變舊」正是這個未驗證點。

兩項都是**單次抓取即可驗證**的性質，在開盤時各花幾分鐘即可，不需要連續觀測。已寫入 `C7-6` 的執行項目。

### 結論

V10 **證據不足並結案**，原因已知且可查證：執行環境不支援跨夜連續運行，而該執行模型已被雲端設計取代。V09 的持久化與恢復部分由本次報告的六個 run 續接紀錄支持（判定「部分符合」）。其餘 V01–V08 由步驟 1–7 判定，不在本步驟範圍。

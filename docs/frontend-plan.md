# 持股儀表板：前端規格與執行計畫

日期：2026-09-09｜版本：v0.1｜狀態：已交付本機第一版；實作選擇、驗證及剩餘差異見 [第一版操作文件](dashboard-v1.md)。以下保留原規劃契約。

## 1. 目標與設計預設

提供繁體中文網頁，讓使用者上傳 Excel 或手動輸入持股代碼、股數及買入價，查看目前持股總市值，以及各股票占整體市值的圓餅圖。

本文件是既有 CSV／CLI POC 的下一階段規格，不代表原 POC 已完成盤中可靠性驗收。依 README，目前步驟 9 仍在觀測中；可先開發介面與離線驗證，正式行情驗收仍須引用後續證據。

以下是可直接展開實作的設計預設，並非使用者逐項指定：

- 單一使用者、一份可保存的持股清單，先供本機使用。
- 預設以 TWD 顯示合計，另保留 TWD／USD 原幣小計。
- 第一版由使用者輸入 USD/TWD 匯率（1 USD = 多少 TWD），不預填可能被誤認為行情的匯率。自動匯率後續再接。
- 「總資產」在本版定義為**已輸入股票與 ETF 的總市值**，不包含現金、不動產或其他資產；畫面主標使用「持股總市值」。
- 買入價代表目前持股的每股平均買入價；同一股票只留一列，由使用者自行整理多筆買入成本。
- 本版增加成本與未實現損益，作為買入價的用途；不包含手續費、稅、股息、已實現損益與歷史匯兌損益。
- 原規劃階段只交付規格文件；後續已依使用者要求實作第一版，未改動既有觀測程序。

## 2. 與現有系統的銜接

| 現有能力／限制 | 本次規劃 |
|---|---|
| `input.py` 接受 `ticker,buy_price,quantity`，整份驗證 | 新增 Excel 解析層，共用欄位驗證，維持原 CSV 契約 |
| `models.py` 已有持股模型 | 網頁持股持久化另外建表，不改寫歷史 run 持股 |
| 官方標的解析與來源映射 | 重用現有邏輯，先格式驗證，再確認標的 |
| `valuation.py` 使用 Decimal，分幣別輸出及品質旗標 | 重用估值，再新增成本、損益、匯率換算與圖表資料 |
| Yahoo 為目前估值來源，其他來源為比較資料 | 沿用來源政策，不能由前端任選比較價代替估值價 |
| `quote`／`monitor`／migration 共用收集鎖 | 不允許每次網頁請求直接執行 CLI quote；設置獨立報價工作流程 |
| `report` 是觀測可靠性報告 | 新增儀表板 API，不把 report 當作持股查詢 API |
| 尚無 HTTP API、Excel 匯入、外匯換算 | 均列為實作工作，不視為既有功能 |

## 3. 畫面與操作流程

採單頁儀表板，上方為匯入與設定，中間為總覽與配置，下方為可編輯持股表格。桌面左右排列圖表及配置清單，手機改成垂直排列。

```text
持股儀表板                       [上傳 Excel] [下載範本]
清單版本／保存狀態               [新增持股] [儲存持股]

顯示幣別：TWD     USD/TWD：[        ] [套用]
[持股總市值]  [投入成本]  [未實現損益／報酬率]
原幣小計：TWD … ／ USD …
報價涵蓋：…/… 檔 ｜ 資料狀態 ｜ 最後取得時間 [更新報價]

[ 各股票市值圓餅圖 ]             [股票／市值／占比清單]

持股明細：代碼、名稱、市場、股數、平均買入價、最新價、
          原幣市值、台幣市值、成本、損益、占比、報價時間、狀態
```

### 首次使用

1. 空白畫面提供「上傳 Excel」與「手動新增」，不顯示虛構資產數字。
2. 上傳後選擇工作表、預覽資料及逐列錯誤；修正後才可套用。
3. 套用匯入預設取代編輯中的整份清單，顯示新增／移除筆數，經使用者確認後取代；不偷偷追加或合併。
4. 手動新增／修改／刪除都先作用於草稿。點「儲存持股」才持久化；未保存時離頁提示。
5. 保存成功後查詢既有報價，必要時排入更新工作。美股換算尚缺匯率時，引導填入匯率。
6. 報價與匯率齊全後顯示整體總市值及配置圖。

### 日常使用

- 開啟網頁載入上次已保存清單、匯率及最新可用估值。
- 編輯草稿不立即改變既有圖表；圖表標示其對應的已保存版本。
- 按「更新報價」回傳工作狀態；等待期間保留前次結果並標示更新中。成功才切換為新快照。
- 第一版不啟用瀏覽器定時抓行情；重複点击更新時合併相同工作並遵守後端冷卻。
- 修改匯率後以現有價格重新換算，不需要重新抓價。

## 4. Excel 與手動輸入契約

第一版支援 `.xlsx`；不接受 `.xls`、`.xlsm`、密碼保護檔案。既有 CLI CSV 功能保留，網頁 CSV 匯入不列為必要項。

| Excel 欄名 | 中文欄名別名 | 必填與規則 |
|---|---|---|
| `ticker` | 股票代碼 | 必填字串，例如 `0050`、`2330`、`AAPL`、`BRK.B` |
| `quantity` | 持有股數 | 必填、大於零；台股整數股，美股允許小數股；單位是股，不是張 |
| `buy_price` | 平均買入價 | 必填、大於零的每股價格；台股 TWD、美股 USD |

- 範本第一列為標頭，股票代碼欄設為文字；提供匿名台美股範例。
- 欄序可不同；中文或英文欄名正規化後必須恰有三個唯一欄位，未知欄位或重複映射拒絕。
- 多工作表列出名稱供選擇；只有一個時自動選取。第一版不做任意券商格式映射。
- 代碼必須保留前導零；數字型代碼儲存格拒絕並提示改用文字重新輸入，不能把 `50` 猜成 `0050`。
- 不執行公式、不採用公式的快取值；必填資料儲存格若為公式、日期、布林或錯誤型別則拒絕。
- Excel 尾端空白列忽略，中間空白資料列回報错误；這是 Excel 專用正規化，不改變 CLI CSV 規則。
- 文字價格不接受幣別符號或千分位逗號；數值儲存格的顯示格式不作為數值來源。後端轉成十進位字串再驗證。
- 台股輸入原始代碼，市場與幣別由系統判定，名稱來自官方清單，不提供自行改幣別的欄位。
- 重複標準化 ticker 整份拒絕並指向首次出現列；不自行平均買入價。
- 格式、數值錯誤時整份不套用；標的不支援或查無時也須修正才能保存。清單服務失敗可保留草稿供重試。
- 匯入畫面顯示工作表、Excel 實際列號、欄位及原因；手動編輯採相同後端規則。
- 建議初始上限：5 MiB 壓縮檔案、500 筆持股、50 MiB 解壓後內容；超限時明確拒絕，解析過程也需設時間與資源上限。

## 5. 計算規則

對持股 i，股數為 Q、最新可用價格為 P、平均買入價為 B：

- 原幣市值 V = Q × P。
- 原幣投入成本 C = Q × B。
- 原幣未實現損益 U = V − C；報酬率 = U / C × 100%。
- TWD 換算係數為 1，USD 換算係數為使用者輸入的 USD/TWD 匯率 R。
- 台幣總市值 = Σ(V × 換算係數)，台幣成本 = Σ(C × 換算係數)。
- 台幣損益 = 台幣總市值 − 台幣成本；整體報酬率以台幣總成本為分母。
- 個股占比 = 該股台幣市值 / 台幣總市值 × 100%，依市值而非成本或股數計算。

成本與市值使用同一個輸入匯率，故此損益不含歷史匯率變化。畫面須呈現此口徑。匯率保存數值、來源 `manual`、輸入時間；輸入時間不是行情時間。

金額、股數、匯率與占比由後端 Decimal 計算；API 以字串傳輸，前端不得用浮點數另算帳務總額。金額顯示兩位小數，占比兩位小數；先加總後四捨五入。各顯示占比可能因四捨五入不恰為 100%，不強改個股數字。

### 缺值與資料品質

- 沒有美股時不要求匯率；有美股但沒有匯率時，保留分幣別小計，整體總額與整體圖表顯示「待輸入匯率」。不得直接加總 USD 與 TWD。
- 缺價不能用零或買入價補值；完整總市值、總損益及完整配置圖不成立。
- 有部分有效價格時顯示「已知持股市值（非完整總額）」、缺價清單與涵蓋檔數。可顯示「已知市值配置」圖，但須明列排除標的，分母只含已知市值。
- 完全無價或分母為零時不畫圓餅圖，顯示具體原因。
- 有有效但延遲／快取／時間未知的價格時，沿用既有品質規則顯示降級估值與警示，不標示即時。
- 休市顯示最近可用的一般交易時段價格及時間；不將休市等同連線錯誤，不計入美股盤前盤後價格。
- 不合格價格沿用現有估值拒絕規則。逐列保留來源、價格時間、取得時間、交易時段及品質旗標。
- 台美股報價時間可能不同；總覽顯示各市場時間範圍，不用單一「現在時間」暗示所有價格同步。

## 6. 圓餅圖與明細互動

- 採環形圓餅圖，中央顯示與當前資料狀態一致的市值名稱、金額及 TWD。
- 預設全部市場，另可切換台股／美股；切換時標題、合計與分母同步變更，避免把市場內占比誤認為整體占比。
- 分配穩定顏色，依市值由大到小排列；滑鼠懸停或鍵盤聚焦顯示名稱、代碼、台幣市值及占比。
- 超過 10 檔時顯示前 9 檔加「其他」；其他為剩餘市值的精確加總，可展開查看，明細仍列出所有股票。
- 圖例、表格提供相同數字，不只用顏色傳達資訊；手機可直接閱讀配置清單。
- 損益同時显示正負號與文字，不只靠紅綠色。欄位都有名稱、單位及錯誤提示，鍵盤可操作。

## 7. 系統架構與 API 草案

採「網頁介面 → 同源 Python HTTP API → 持股／估值服務 → PostgreSQL」，報價由背景 worker 經現有 provider 模組取得。前端不直連資料庫或行情服務。

前端框架、圖表套件、HTTP 框架與 Excel 函式庫於執行步驟 1 確認，依屆時維護狀態、授權與現有 Python 3.14 環境相容性固定版本及鎖定檔；本文件不預先宣稱套件已驗證可用。

| API 草案 | 用途／重要行為 |
|---|---|
| `GET /api/portfolio` | 取得已保存持股、匯率及 revision |
| `POST /api/imports/preview` | 上傳 Excel 及可選 sheet；回傳工作表選項、正規化資料與列錯誤，不保存正式持股 |
| `PUT /api/portfolio` | 提交完整清單、匯率、預期 revision；驗證後原子保存，衝突回 409 |
| `GET /api/portfolio/valuation` | 回傳對應 revision 的估值快照、原幣與 TWD 合計、圖表資料及完整度 |
| `POST /api/portfolio/refresh` | 排入或合併更新工作，回 202 與 job_id；不在 HTTP 請求中長時間抓價 |
| `GET /api/jobs/{job_id}` | 取得 queued／running／succeeded／partial／failed 狀態及原因 |
| `GET /api/templates/holdings.xlsx` | 下載匿名格式範本 |

所有數值用十進位字串，時間用含時區的 ISO 8601，顯示時轉 Asia/Taipei。估值包含 `portfolio_revision`、`valuation_id`、`computed_at`、匯率中繼資料、逐股數值與品質，以及 `complete/partial/degraded/unavailable` 狀態。輸入錯誤使用一致的 `code/message/sheet/row/field` 格式。

建議新增 portfolios、portfolio_positions、refresh_jobs 等資料表；portfolio 保存 revision 與手動匯率，positions 每份清單內 ticker 唯一。估值快照須記錄所用持股版本、報價參照與匯率，避免價格或持股更新造成同一畫面上下不一致。

### 報價與既有 monitor 的界線

1. API 的讀取與持股保存不得取得長時間收集鎖，不應阻塞既有 monitor。
2. 儀表板以官方識別、估值來源與品質規則選價，不得僅依 ticker 任取歷史最新列。
3. 更新工作固定持股版本，完成後前端只接受仍符合當前版本的結果；舊版本结果不覆蓋新清單。
4. 現有 monitor 的持股輸入固定，新增網頁持股不會自動進入觀測清單。背景 worker 必須處理完整的網頁持股集合。
5. 實作期用獨立測試 schema 隔離，避免影響進行中的觀測；開發前先確認鎖與設定是否能依 schema 隔離。
6. 正式切換時讓 worker 成為該環境唯一報價收集者。若仍與 monitor 共用 schema，更新回傳 busy／待重試且保留既有估值，不停掉 monitor，也不繞過鎖。

## 8. 保存、部署與隱私

- 只保存確認後的正規化持股，不長期保存原始 Excel；預覽檔解析後清除，錯誤流程亦須清理。
- 不將持股放入 URL、分析追蹤或瀏覽器永久儲存；日誌不記錄原檔內容與完整持股金額。
- 延用伺服器端環境變數及憑證設定，API Key、DB 密碼不下發前端。
- 本版服務只綁定 localhost，不含登入與公開網路部署。若要遠端存取，登入、授權、TLS 及請求防護須先補齊。
- 本機版仍限制 Host／Origin、採同源請求並保護寫入端點，拒絕任意跨站寫入。
- Compose 新增 web／worker 的安排需與現有 app 分開；延用既有 PostgreSQL external network，不接管資料庫容器或 volume。
- 新 migration 在隔離環境驗證，正式套用安排維護時間並遵守收集鎖；不在每次 API 啟動时自動執行 migration。

## 9. 執行步驟與交付條件

| 步驟 | 工作 | 交付物與完成條件 |
|---|---|---|
| 1. 契約與開發環境 | 確認本文件預設；驗證前後端、Excel 與圖表依賴；確認 schema／鎖隔離 | 技術選型紀錄、鎖定檔、API schema、隔離開發設定；既有觀測不受影響 |
| 2. 介面雛形 | 以固定匿名資料完成儀表板、匯入預覽、編輯表格、空白與錯誤畫面 | 桌面／手機可操作雛形；假資料清楚標示，沒有假即時報價 |
| 3. 輸入與保存 | 實作 Excel 解析、共用驗證、官方解析、revision、資料表與範本 | 匯入與手動輸入結果一致；重啟後可讀回；失敗不覆蓋清單 |
| 4. 估值與配置 | 共用既有 Decimal 核心，補成本、手動匯率、合計與占比 | 固定案例精確通過；缺價與缺匯率不產生完整總額 |
| 5. 行情整合 | 加入查價讀取、背景工作、合併請求、鎖忙碌與版本保護 | 真實來源可更新；重複點擊不重複收集；舊工作不覆蓋新版本 |
| 6. 完整 UI | 串接 API、配置圖、狀態提示、表格排序、手機與鍵盤操作 | 完成上傳→預覽→保存→更新→查閱的完整流程 |
| 7. 部署與驗收 | Compose、migration、操作說明、離線與整合測試 | 可啟停、保存資料、呈現斷線狀態；附驗收證據與已知限制 |

依賴順序：1 → 2 → 3 → 4 → 5 → 6 → 7。步驟 2 使用假 API，避免等待真實行情；步驟 5 開始前必須確認不干擾 POC 觀測。

固定計算案例（全部為測試值，不是行情）：

- 2330：10 股、買入價 TWD 80、現價 TWD 100 → 市值 1,000、成本 800。
- AAPL：2 股、買入價 USD 8、現價 USD 10；USD/TWD = 30 → 台幣市值 600、成本 480。
- 合計 TWD 1,600，成本 TWD 1,280，損益 +TWD 320，報酬率 25%；占比 62.50%／37.50%。
- 移除 AAPL 報價後，完整總市值與總損益為不可用；只顯示已知市值 TWD 1,000、涵蓋 1/2 檔。部分配置圖中 2330 為 100%，必須標示 AAPL 未納入。

以單元測試驗證匯入、Decimal 計算及缺值；API 整合測試驗證原子保存、版本與工作鎖；瀏覽器端到端測試驗證關鍵使用流程。真實報價測試只驗證整合與狀態，不要求行情在測試期間保持固定。交付時另跑既有回歸測試，確認 CLI 行為未改變。
